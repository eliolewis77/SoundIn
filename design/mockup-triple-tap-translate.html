连击触发翻译 · 设计稿

语音输入落进输入框后，鼠标还停在里面，连按三次空格即触发翻译：有选区就替换选区，没选区就替换全部。
触发键、连击次数、间隔上限全部可自定义。翻译走「文字优化」页那一套 API 配置，不新增配置档。

1交互时序

1
第 1 次按下触发键
用辅助功能（AX）记下当前选区：范围 + 选中的文字。按键照常进入输入框，此时视觉上无异常。
2
第 2 次
间隔在阈值内（默认 0.6s），计数 +1，继续等。
3
达到连击次数 → 触发
读取原文：优先用第 1 步记下的选区；无选区则读整个输入框（kAXValue）。
4
调 API 翻译
复用润色那一档的地址 / Key / 模型，system prompt 换成翻译指令。HUD 显示「翻译中…」。
5
写回
用 AX 把选区恢复成第 1 步记下的范围（没有就用 ⌘A 全选），再走现有的粘贴通道。剪贴板原内容照旧保存并还原。
6
收尾
翻译成功 → 译文覆盖上去，敲出来的键自然被吞掉；⌘Z 可整体撤销。
翻译失败 → 原文不动，额外发 N 次退格删掉刚才的按键，HUD 报错。计数清零。

2连击判定规则

必须遵守的三条

  • 按下去的长按自动重复（isARepeat）不算一次
  • 中间夹了任何别的键 → 计数清零重来
  • 超过间隔上限 → 计数清零
第 2 条是关键。触发键默认是空格，问题不大；一旦改成字母，比如 P，那么「apple」里的 p 会被别的键打断，不会误触；而连打的「ppp」会触发——这是连击手势的固有代价，靠「必须是干净的连续 N 次同键」把误触率压到最低。

触发时不做的事

  • 不吞键（方案 B，见下节）
  • 不在录音进行中触发
  • 不在设置页录制快捷键时触发
  • 触发后计数立即清零，第 4 次按下重新开始数

3按键要不要真拦下来

方案 B · 不拦，靠译文覆盖推荐

  • 复用现有 NSEvent 全局监听，不新增事件机制
  • 对输入法零干扰，Space 选词照常
  • 任何时刻都能用，不限语音输入后
  • 失败回退只需发 N 次退格
  • 翻译那 1–2 秒能看到敲出来的字符
  • 依赖 AX 能写回选区（绝大多数 App 支持）

方案 A · 用 CGEventTap 吞掉备选

  • 输入框全程干净，一个字符都不留
  • 要新增第三套键盘监听，和现有 Carbon / NSEvent 并存
  • 为了不影响正常打字，得限定「语音输入后 N 秒内」才拦截
  • 窗口内正常打字会有最多 0.6s 延迟（等凑满连击）
  • 吞掉的键要补发，输入法/游戏场景风险高
倾向 B。方案 A 要为「让字符不出现」付出延迟和输入法风险，而 B 的代价只是翻译那 1–2 秒里看到几个字符，随后被译文覆盖——连击本来就是用户主动敲出来的动作。选 B 也让「自定义触发键」这条路走得通：换成字母键时，方案 A 拦字母会直接破坏正常打字。

5触发键可选项

触发键只从「按下后只会往输入框里插字符」的键里选。以下按键一律排除，因为它们在触发前就已经产生了副作用——

可选说明
Space（默认）最安全。正常打字不会连打三次空格
A–Z　0–9连打同一字母会误触，靠「中间夹别的键就清零」缓解
. , ; ' " / \ - = [ ]同上
Return / Enter 排除：会提交表单、发送消息
Tab 排除：会切换输入焦点，连按三次直接跳走
Esc 排除：已用于取消录音，还会关掉各种弹窗
Delete / Backspace 排除：会直接删掉输入框里的内容
方向键 / Home / End / PageUp / PageDown 排除：会移动光标，且长按自动重复难判定
F1–F12 排除：F1 帮助、F3 查找、F5 刷新，各应用行为不一
⌘ ⌃ ⌥ ⇧ 排除：走 flagsChanged 而非 keyDown，拿不到普通按键语义
录制时怎么处理非法键。用户按了 Return，录制不结束，提示「该键会改变输入状态，请改用字母、数字或空格」，按钮保持录制态让用户直接重按。Esc 仍然是取消。

7边界情况

场景行为
无辅助功能权限HUD 提示去系统设置授权，不动输入框
焦点元素读不到内容（终端、游戏、PDF）不翻译，HUD 提示「未识别到可翻译内容」，敲出的字符保留
正在录音不触发翻译，避免误触
在设置页录制快捷键不触发翻译
触发键与单击/长按快捷键撞键录制时校验并提示，换一个键
输入框为空直接返回，不发 API 请求
翻译失败 / 超时（30s）原文不动，退格删掉敲出的字符，HUD 显示失败
翻译中用户又敲了键盘仍按原选区写回；失败时不退格，保留现状
翻译成功写入译文，⌘Z 可整体撤销
统计口径不计入听写统计，也不写入输入历史（不是语音输入）
